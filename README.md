# 星むすびプロダクション

配信アプリ文化をモチーフにした、オリジナルのライバー育成 × 箱庭 × 事務所経営ゲームです。IRIAMや関連企業の公式作品ではありません。実在する配信者・ロゴ・素材は使用していません。

4人から最初のライバーを選び、配信・育成・スカウトで事務所を成長させます。事務所Lv30で大手事務所へ到達し、その後もプレイできます。1日45秒、1か月30日。画面上で一時停止・1/2/4倍速を切り替えられます。

## 起動

Node.js 22.18以降を推奨。ランタイム依存はReact / React DOMのみです。

```bash
npm install
npm run dev
```

開発用URL: http://localhost:5186/ （ポート固定・他のアプリへ誤接続しない設定）。サーバーは同じWi-Fiの端末からアクセスできます。Windowsファイアウォールの設定により接続できないことがあります。

```bash
npm run lint        # TypeScript厳格チェック・未使用コードの確認
npm test            # Node標準テストランナーによるゲームルールの検証
npm run build       # TypeScript + Vite production build
npm run preview     # distの配信
npm run test:browser # 起動済み5186番サーバーをEdgeで操作検証
```

Windowsの制限付き環境でesbuildが親ディレクトリを読めない場合は、`npm run build -- --configLoader runner` で同じビルドを実行できます。

`lint`はTypeScriptコンパイラによる静的検査です。ESLintは導入していません。ブラウザテストはMicrosoft Edgeを使います。必要なら `playwright.config.ts` のchannelを変更してください。

## 遊び方

1. 最初のライバーを選んで「配信」から配信を開始。約12ゲーム秒で結果が届きます。
2. 「ライバー → スカウト」で新しい仲間を迎えます。初期の30万Gで早期からスカウト・建設できます。
3. 「建設」で施設を選択し、空いた2×2マスをタップ。緑のプレビューを確認して確定。確定前はキャンセルできます。
4. 疲れたら詳細画面から休憩。「おまかせ配信」は得意な配信を1日1回行い、疲労40以上で自動休養します。自動配信の結果は履歴と通知へ記録し、毎回ダイアログは開きません。
5. 事務所Lv2でスタッフ、Lv3で育成、Lv4で10×10フロア、Lv5で月間イベント、Lv7でコラボが解放されます。
6. 実績画面では達成報酬を受け取れます。毎月末に給与・家賃・維持費が引かれるため、無理な先行投資に注意しましょう。

全24人（既存20人＋男性ライバー4人、所属上限20人）、施設12種類、スタッフ5職種、月間イベント5種類、NPC8社、ランダム出来事30タイトル、実績24種類を収録。

## 設計とルール

- React: HUD、操作メニュー、シート、ライバー詳細。Canvas 2D: 床、施設、人物、吹き出し、ON AIR、カメラ。
- 描画は `requestAnimationFrame`。ゲーム更新は250ms間隔。毎フレームReact stateを更新しません。
- 日時・活動の進行はモーダル、建設モード、非表示タブで停止。オフライン報酬はありません。
- スカウトは未所属キャラクターから重複なしで抽選。狙ったレアリティの候補が尽きた場合は残り候補から補完します。所持するSSRが多い等の状況では、名目確率と実際の候補分布が異なります。
- 施設は2×2タイル。辺が接している施設を隣接と判定します。拡張はLv4/10/20/30の報酬として無料で自動実行。
- 能力は100上限。ランクはD〜S1、+6ptで昇格、−4ptで降格。配信履歴は1人30件、月次レポート12件、通知履歴40件。
- 家賃15,000G/月＋施設1つ1,500G/月＋スタッフ給与。採用時は1か月分の契約費を支払います。
- 配信結果の売上は総売上です。40%をライバーへの還元として月末に精算します。経営画面に精算予定額を表示します。
- 月末に所持金がマイナスなら経営危機を1か月加算。所持金を戻し月間黒字化で危機を解除。危機3か月で終了。
- 配信ブース強化は成果1/1.5/2倍、休憩施設強化は回復1/1.5/2倍、育成施設強化は成長上限5まで加算。装飾施設の強化は見た目のLv表示が中心です。
- イベントは月内配信ファン数の累積。指定スタイルは1.4倍。月末に8社のNPCと比較し、最大9位までの報酬を決定します。
- グッズはLv10以降、ファン数に比例した日次収入。広告案件はLv15以降、月1回。Lv20でスカウト品質が上昇。Lv25以降のエントリーは大型大会になり、NPCの強さ1.8倍・賞金2倍。
- 音声は初期OFF。音源がなくてもWeb Audioによるオリジナルの簡易BGM・効果音でプレイ可能。

## 保存

localStorageキー `hoshimusubi-save-v1`、スキーマversion 2（保存キーは旧版と共通）。配信完了・育成完了・各操作・日付変更・30秒間隔・非表示化に保存します。

型・範囲・施設重複・配列構造を確認してから読み込みます。不正データは自動で上書きせず、復旧画面を表示。設定でJSONの書き出し・復元ができます。旧version 1は進行を保持してversion 2へ移行し、その他の未対応versionは読み込みを拒否します。保存形式の変更時には明示的な移行処理を追加してください。

## 素材の差し替え

現状の人物・家具・床はオリジナルのSVG / Canvas図形です。添付の参考画像そのものやトレース素材は含みません。

1. `public/images/streamers/` に立ち絵・ミニキャラを配置。
2. `src/game/assets.ts` の `STREAMER_ASSETS` に `portrait` / `mini` の相対パスを設定（先頭 `/` は不要）。立ち絵は縦長、ミニキャラは足元中央基準。
3. `public/images/facilities/` に透過施設画像を配置し、`FACILITY_ASSETS` に指定。
4. 画像なし・画像ロード失敗では図形描画を継続します。ブランド名は `BRAND` に集約。

音源を追加する場合は `public/sounds/` の対応ファイルを配置し、`AUDIO_FILES_ENABLED` で該当キーを `true` にしてください。OFFのキーはWeb Audio版を使用します。

検証結果・計測条件は [docs/VERIFICATION.md](docs/VERIFICATION.md) を参照してください。

推奨する今後の制作仕様は [docs/ASSET_SPEC.md](docs/ASSET_SPEC.md) を参照してください。

## GitHub Pages

`vite.config.ts` は `base: './'`。単一HTML・内部ルーティングなしのため、リポジトリ名配下に配置できます。画像URLは `import.meta.env.BASE_URL` を使用します。

1. GitHubリポジトリへpush。
2. Settings → Pages → Source を **GitHub Actions** に設定。
3. mainブランチへのpushまたはworkflow_dispatchで `.github/workflows/pages.yml` が検査・ビルド・公開します。

公開先: [星むすびプロダクション](https://altogrow-ir.github.io/liverproduction/) 。リポジトリは `altogrow-IR/liverproduction`、公開元は `main` です。

本番URLの操作・保存確認は、環境変数 `TEST_URL` に公開URLを設定し `node scripts/verify-build.mjs` で実行できます。

## ファンからのお願い（2026-09-20追加）

初配信の後はホームの目標カードから、または「その他 → ファンのお願いと目標」から開けます。配信2回、おすすめスタイルの配信1回、疲労のあるライバーの休憩完了1回を、所属メンバー全員で達成します。おまかせ配信・自動休養も対象です。

各報酬は3,000 / 2,000 / 1,500Gと事務所EXP各10。3件を受け取るとファンのお便りが届き、「次のお願いを開く」で雑談 → 歌 → 企画のテーマが巡ります。時間制限や日次リセットはなく、次のお願いを開くまで現在の進捗を保持します。同じ配信が「2回配信」と「おすすめスタイル」の両方に数えられます。

旧version 1セーブは既存の資金・所属・育成状態を維持し、お願いだけ第1便・進捗0から開始します。報酬は一度だけ受取可能。お願いの定義は `src/game/requests.ts`、表示は `src/components/RequestBoard.tsx` に分離しています。

## 私だけの推し

ライバー本人の「きみとの絆」が40になると、詳細画面の「私だけの推し」から名前とイラストを無料で何度でも変更できます。キャラクターID・能力・育成・ファン数を保持し、名前の重複も許可します。名前は日本語・英数字・絵文字を含む1〜20文字。履歴の名前は当時の記録として残します。

プロフィール画像と箱庭用の画像を選び、拡大・位置を調整して「この姿で決定」で保存します。同じ画像を箱庭に使えるほか、専用ミニキャラ画像も指定できます。箱庭は丸いアイコンか全身表示を選択でき、移動時は画像が揺れます。別ポーズの自動生成は行いません。変更・リセットは確定まで進行に反映しません。

画像入力はPNG/JPEG/WebP、10MB・2000万画素まで。プロフィールは最大768×1024、箱庭は256×256または256×352へ調整し、1画像1MB以下でIndexedDB `hoshimusubi-media` に保存します。進行データは画像参照のみをlocalStorageに保存し、保存失敗時は以前の設定を保持します。外部アップロードは行いません。

設定のJSONバックアップには使用中の画像も含まれます（上限64MB）。旧版の画像なしJSONも復元できます。画像は形式・実デコード・寸法を確認し、画像保存後に進行を置き換えます。画像が見つからない場合も元の姿でゲームを続けられますが、画像付きバックアップの作成には画像の再選択が必要です。

男性ライバーは陽向ハルト（最初から選択可能）、奏木イツキ、橘タクミ、風間ハヤテを追加しました。既存20人は保持し、男性4人も同じ育成・配信・スカウト・カスタマイズに対応します。
